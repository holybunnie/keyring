# M0.2 — live capture, Run A (Account-only grant)

**Captured 2026-09-06 from a Binance Agentic session authorized through Claude Code, a DOCUMENTED supported client (Part 0.2).** Raw responses are append-only and hash-chained at [`evidence/raw/0002-m0-oauth-discovery.jsonl`](../evidence/raw/0002-m0-oauth-discovery.jsonl) and [`evidence/raw/0003-m0-tools-list.jsonl`](../evidence/raw/0003-m0-tools-list.jsonl). Egress country GB. No tool was invoked; every request was a protocol-level `initialize` or `tools/list`. No financial state could change.

## Authorization surface

**OBSERVED:** `https://agent.binance.com/.well-known/oauth-authorization-server` returns:

| Field | Value |
|---|---|
| `authorization_endpoint` | `https://accounts.binance.com/agentic-oauth/authorize` |
| `token_endpoint` | `https://accounts.binance.com/oauth-agentic/token` |
| `token_endpoint_auth_methods_supported` | `["none"]` |
| `code_challenge_methods_supported` | `["S256"]` |
| `client_id_metadata_document_supported` | `true` |
| `registration_endpoint` | **absent** |

**OBSERVED:** There is no Dynamic Client Registration endpoint. The gateway advertises Client ID Metadata Document support instead, and the observed `client_id` was the URL `https://claude.ai/oauth/claude-code-client-metadata`.

**OBSERVED:** The authorization request issued by the client carried `response_type`, `client_id`, `code_challenge`, `code_challenge_method`, `redirect_uri`, `state` and `resource`. It carried **no `scope` parameter**.

**OBSERVED:** The resulting grant recorded scope `mcp:account:read`, with a one-month expiry and **no refresh token issued**.

**INCONCLUSIVE:** Whether `mcp:account:read` is a gateway default for a scope-less request, or the product of the operator's consent-screen selections, is not resolved by this run. Both remain possible and neither is claimed.

## Tool surface under `mcp:account:read`

**OBSERVED:** `initialize` succeeded (HTTP 200) and returned `serverInfo.name` `Tesla-MCP-Server`, protocol `2025-06-18`, and capabilities `tools` and `resources`.

**OBSERVED:** No `Mcp-Session-Id` response header was returned. The gateway answered `tools/list` without one.

**OBSERVED:** `tools/list` is paginated by `nextCursor`. Two pages returned **60 advertised tools**:

| Group | Count |
|---|---|
| `spot` | 10 |
| `margin` | 9 |
| `futures_usds` | 12 |
| `futures_coin` | 12 |
| `wallet` | 9 |
| `convert` | 5 |
| `analysis` | 1 |
| META (`tool_search`, `tool_execute`) | 2 |

**OBSERVED:** Every one of the 58 non-META tools is a read or query operation — for example `spot.getAccount`, `spot.getOpenOrders`, `margin.queryMaxBorrow`, `futures_usds.positionInformationV2`, `wallet.withdrawHistory`. **No order-placement, cancellation, transfer, borrow or repay tool appears in the advertised surface under this grant.**

**OBSERVED:** The server's own `instructions` string names three tools in a `{verb}_{product}_{operation}` form — `create_spot_newOrder`, `create_wallet_sapi_userUniversalTransfer`, `get_futures_usds_accountBalance`. None of these names appears in the `tools/list` response, which uses a `{product}.{operation}` form.

**OBSERVED:** `tool_execute` is advertised and described as *"Execute any visible tool. Equivalent to tools/call but with the tool name in arguments, for calling hidden tools in META mode."* `tool_search` accepts a `category` enum that includes `trade`, `transfer`, `borrow-repay` and `capital`.

**INCONCLUSIVE:** Whether the absent write tools are hidden by scope filtering, by META-mode gating, or by a naming change since the instructions were written, is not resolved. This run cannot distinguish the three, and no claim is made about which applies.
