# M0 — measured Claude Code record

This document records the authenticated Binance Agentic session used by the build. It covers one Agentic sub-account and the Claude Code default and manual permission modes. The raw records are retained under [`evidence/raw/`](../evidence/raw/).

## Measurement boundary

**OBSERVED · harness:** KEYRING's authority tests use a no-state-change boundary. Each test request is sent with parameters designed to be rejected before matching or execution. Balances, positions, and open orders are captured before and after.

**DOCUMENTED:** Binance advises users not to paste the MCP endpoint into an AI chat or open the endpoint directly in a browser. The measurement followed that guidance.

## Grant A — account access

**OBSERVED · harness:** The authenticated `tools/list` surface for `mcp:account:read` contained 60 tools. All were read or query operations. No order, cancellation, or transfer capability was advertised.

Raw discovery: [`0003-m0-tools-list.jsonl`](../evidence/raw/0003-m0-tools-list.jsonl).

**OBSERVED · harness:** `spot.getAccount` returned HTTP 200 and served as the connection check. The Agentic sub-account had zero balances.

Raw control: [`0004-m0-positive-control.jsonl`](../evidence/raw/0004-m0-positive-control.jsonl).

## Controlled tests

**OBSERVED · harness:** The Spot test used `BTCUSDT`, quantity `0.00001`, and limit price `0.01` USDT. The request reached Binance validation and returned `-1013 Filter failure: PERCENT_PRICE_BY_SIDE`.

**OBSERVED · harness:** The USDⓈ-M Futures test returned `-4013 Price less than min price`.

**OBSERVED · harness:** The COIN-M Futures test returned `-1111 Precision is over the maximum defined for this asset`.

All three responses were parameter-validation failures before the matching engine. None changed the account state.

Raw probes: [`0007-full-proof-probes.jsonl`](../evidence/raw/0007-full-proof-probes.jsonl) and [`0008-run-c-coinm.jsonl`](../evidence/raw/0008-run-c-coinm.jsonl).
